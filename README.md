# SENS LAB V1.0

无畏契约手游智能灵敏度实验室。独立、免费的浏览器本地工具，不读取或修改游戏进程，无后端、无收费 API，不使用官方美术资源。

目标地址：**https://460728888-alt.github.io/sens-lab/**。这只是预期部署地址，是否已上线请以仓库 Actions 和 Pages 的实际状态为准。

## 本地运行

需要 Node.js 22+ 和 npm。

```bash
npm install
npm run dev
```

浏览器打开终端显示地址下的 `/sens-lab/`。生产验证：

```bash
npm ci
npm test
npm run build
npm run preview
```

手机可在同一局域网访问开发机 IP 的 5173 端口和 `/sens-lab/` 路径。不要把远程云容器的 localhost 当成手机可直接访问的地址。

## 使用流程

1. 点击「开始检测」，填写设备型号、操作指法、陀螺仪状态和可选屏幕尺寸。
2. 在「灵敏度设置」按游戏真实名称填写参数；字段名称、数值或文本均可编辑。网页增益是另一项独立的模拟参数。
3. 选择甩枪、微调、跟枪、转向训练，点击开始后在画布内**滑动**。点击目标不会移动准星。画布短边的 1% 为一个模拟单位，滑动改变视角，准星保持中央。
4. 每轮 24 秒。完成后自动展示报告，原始触控事件、30 Hz 误差轨迹、指标及参数快照自动保存。
5. 在「录像分析」选择本地视频、暂停、定位，分别点击准星与目标中心，再记录关键帧；选择区间和配置，填写同条件任务标识并保存。
6. 在「参数实验」建立候选配置，交替重复基准/候选测试。满足证据条件才给出方向性建议；可保存报告和导出 JSON。

首次使用无任何伪造测试结果。首页轨迹图明确标为示意，不计入分析。网页训练可以用鼠标调试，但鼠标和触屏记录不会混合比较。

## 已实现

- React + TypeScript + Vite + Tailwind CSS，中文响应式界面，Hash 路由适配静态托管刷新。
- IndexedDB 自动保存设备、灵敏度配置、原始轨迹、录像标注和报告历史。配置修改不改变既有记录快照。
- Canvas 2D + Pointer Events 四项滑动训练，开始、暂停、继续、重测；处理 pointercancel、丢失捕获、失焦、后台切换、尺寸变化、长帧中断。
- 手动录像标注、近似时间步进、区间选择、关键帧误差曲线、保存记录和多录像对比。
- 真实重复测试的 A/B 比较、保守区间、样本与可比性筛选、辅助指标保护条件。
- JSON 导出、单轮删除、报告快照与历史。原始数据可离线检查；没有账户和服务器同步。
- GitHub Pages Actions，PR 检查，单元测试和 Chromium/WebKit Playwright 测试。
- 自动视觉接口预留，**不提供也不宣称已经实现自动目标识别**。

## 指标定义

### 网页触控

每轮使用固定 8 × 3 秒目标暴露协议；目标方向与距离用固定随机种子 731 生成，相同模式的位移顺序一致，便于对照。微调目标更小；转向目标可能在画布之外，显示方向提示。跟枪目标每 3 秒水平反向，伴随平滑垂直运动。

- 误差：中央视角与目标的欧氏距离，单位为画布短边的 1%。平均误差、RMS、误差标准差由固定活动时间网格上的采样计算。
- 首次瞄准时间：目标出现后，第一次进入目标半径所需的活动时间；未到达记为 `null`。比较时以目标窗口 3000 ms 惩罚，不把失败当作 0。
- 稳定命中：进入目标后连续保持至少 160 ms；到窗口结束仍未曾稳定命中则失败。跟枪以持续误差为核心，命中比例不用于推荐。
- 过冲：模拟视角沿初始目标方向的投影越过目标超过目标半径。它是几何启发式指标，不是对玩家意图的识别。
- 修正次数：沿初始目标方向的移动投影反向，忽略单次不超过 0.15 单位的变化。该去抖阈值是协议常数，非经过外部验证的人体工学结论。
- 未到达率：窗口内从未进入目标半径。与未稳定命中率分别呈现。
- 最终误差：每个 3 秒窗口结束时的位置误差。
- 滑动路径：原始触控位移乘网页增益后的累计长度；原始未增益位移可从导出的 touches 重算。重滑计数按目标窗口统计，多触点只跟踪首个主触点。
- 路径效率：初始直线距离 / 增益后路径长度，上限 100%；不是“匹配度”。
- 跟枪反向响应：目标水平反向后，首个方向一致且大于 0.15 单位的水平滑动响应。显示已测得事件数；未响应不伪造零值。

每轮至少 20 个移动事件、总位移超过 1 单位，且无中断才视为有效。暂停/继续保留轨迹但本轮不用于推荐。尺寸变化会暂停，建议直接重新测试，避免跨尺寸坐标混用。30 Hz 为计算采样频率，并非触摸硬件采样率。

### 录像

标注坐标归一化到原始画面，误差 = `sqrt((Δx × 宽)² + (Δy × 高)²) / 画面对角线 × 100`。画面黑边与播放器缩放通过实际显示区域处理。录像误差的单位与网页训练不同，**不混合数值或直接换算灵敏度**。

只解码当前播放器帧，不保存整段视频帧数组。JSON/IndexedDB 只保存文件名、尺寸、区间、配置和坐标等信息，不包含原视频或截图。换视频及卸载页面释放 Blob URL。视频不可解码时显示错误；推荐 H.264 MP4。按钮的 1/30 秒步进是近似时间定位，不声称获得视频准确帧编号。

## 推荐算法与限制

代码见 `src/lib/experiments.ts`，属于透明的探索性单人实验规则，不是经临床或大规模玩家研究验证的最佳参数模型。

- 以整轮训练或独立录像为样本单位，绝不把一轮内大量采样点当成独立实验。
- 每组至少 3 次有效独立记录。建议 5–10 次，基准—候选—候选—基准交替，尽量减少熟练度、顺序与疲劳效应。
- 基准与候选误差均值差采用保守的 t 近似区间：`均值差 ± t × sqrt(sA²/nA + sB²/nB)`。t 临界值按较小样本数量取保守阶梯值；均值区间使用同一保守规则。
- 改善区间的下界必须大于基准误差均值的 5%，同时 RMS 不增加超过 10%；离散目标任务还检查瞄准时间（最多增加 10% + 30 ms）、过冲/未命中（最多增加 5 个百分点）、修正（最多增加 10% + 0.2）。这些是明确标注的产品判定阈值，不是已验证的最优阈值。
- 样本不足、差值不稳定、退化或多参数一起改变时拒绝强行推荐。输出初步证据，不输出虚假的置信百分比或匹配度。
- 网页实验只允许改变网页增益；比较要求配置当前快照一致、相同设备资料、输入类型、尺寸（容差 2 CSS px）和协议。不同游戏参数的网页结果不能归因到游戏参数。
- 真实游戏录像实验仅允许一个游戏数值参数变化，网页增益不变。要求任务标识相同、画面宽高比接近、分析时长相差小于 0.5 秒。每段至少 8 帧，大致等间隔，覆盖两端；每组至少 3 段。
- 录像只判断标注位置误差与 RMS。相同任务、距离、武器、设备和标注规则仍需用户确认；不能可靠阻止用户把同一源视频重复上传为独立记录。人工挑帧和标注误差限制可信度。
- 录像与网页证据分别呈现；网页改善不推导游戏改善。陀螺仪只作为设备条件记录，网页不模拟陀螺仪传感器；可用真实录像单独验证相关实际参数。
- 多候选筛选未校正多重比较；所有建议需要新一轮独立验证，不能解读为人口总体统计结论。

## 浏览器与隐私

目标为现代 iPhone Safari 和 Android Chrome，也适配平板与桌面。`playsInline` 用于 iOS 内联播放；画布 `touch-action: none` 防止训练滑动触发页面滚动；其他页面保持正常滚动。视口/DPR 变化暂停训练。IndexedDB 或存储配额失败时提示仅本次会话保留并建议导出；清除浏览器数据会丢失记录。JSON 包含设备型号、参数、原始操作数据和录像文件名，分享前自行检查。

不支持 Pointer Events 时禁止启动触控测试，录像和资料功能仍可用。不支持 Canvas 2D 时显示错误。无全屏 API 依赖，无自动音频播放，无摄像头权限请求。当前未实现离线 Service Worker；首次加载资源需要网络，本地视频处理本身无需网络。

## 自动视觉扩展（第四阶段）

`src/lib/vision.ts` 提供 `VisionAdapter`、`VisionFrame`、`VisionDetection` 和 `VisionRegistry`。未来可实现 OpenCV.js 或 ONNX Runtime Web 适配器，支持初始化、逐帧检测、AbortSignal 取消与资源释放。V1 不下载模型、不返回伪检测结果。新增模型必须对人工标注验证，限制逐帧分辨率与内存，并把模型置信度与灵敏度实验结论分开。

## GitHub Pages 部署

已配置：

- `vite.config.ts` 中 `base: '/sens-lab/'`。
- Hash 路由，例如 `/sens-lab/#/video`，刷新不依赖服务器重写。
- `.github/workflows/deploy.yml` 对 `main` push / 手动运行构建；PR 只检查。
- `npm ci` → 单元测试 → `npm run build` → Playwright → 上传 `dist`。
- 部署 job 使用 `pages: write` 和 `id-token: write`，目标环境 `github-pages`。

仓库管理员需要在 **Settings → Pages → Build and deployment → Source** 选择 **GitHub Actions**。然后推送代码至 `main` 或合并 PR。无需购买域名或服务器。仓库应具备 GitHub Pages 免费使用条件（通常使用公开仓库）。

如果当前开发环境不能推送，在自己的电脑执行：

```bash
git clone https://github.com/460728888-alt/sens-lab.git
cd sens-lab
# 将交付压缩包中的项目文件覆盖到当前目录，包括隐藏的 .github 目录。
# 不复制 node_modules、dist 或 .git。
npm ci
npm test
npm run build
git add .
git commit -m "feat: implement SENS LAB V1.0"
git push origin main
```

也可网页上传全部源码，但务必保留 `.github/workflows/deploy.yml` 和 `package-lock.json`。在 Actions 确认检查与部署均为绿色，再访问目标网址检查页面及静态资源。未检查部署结果之前，不应声称已部署成功。
